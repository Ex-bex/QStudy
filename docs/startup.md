# Запуск и сохранение данных

В корне четыре кнопки установки и запуска: `Install-QStudy.cmd`, `Start-QStudy.cmd`, `Start-QStudy-LAN.cmd`, `Start-QStudy-Internet.cmd`, а также **`Stop-QStudy.cmd` для остановки всего сайта**. Windows-запуск выполняется без Docker. Для первой установки нужен интернет. Установщик проверяет версии и контрольные суммы загружаемых компонентов, ставит зависимости по зафиксированным файлам.

## Выбор существующих данных

Обычная установка использует `backend/studyhub.db`, `backend/uploads/` и `backend/.env`. Если данные остались только в `deployment/data/backend/` от контейнерного запуска, они используются на месте вместе с прежними настройками. Другая пустая база рядом не создаётся. Если найдены две разные базы, стартер просит один раз выбрать нужную, сохраняя обе. Выбор сохраняется относительным путём.

Все три режима открывают выбранную базу. Смена LAN на интернет меняет адрес в окружении процесса; она не импортирует данные и не перезаписывает SMTP, ключ ИИ или пароль администратора. Миграции схемы сохраняют существующие записи. Закрытие окна стартера не останавливает фоновые процессы.

Если аккаунты «пропали», проверьте в админке выбранное хранилище. Не удаляйте `.env` или базу для исправления запуска. Сохраните обе папки данных, прежде чем менять выбор.

## Перенос

1. Войдите администратором и скачайте **проект со всеми данными** в разделе «Система».
2. Передайте ZIP напрямую владельцу нового компьютера. Он содержит секреты; публиковать его нельзя.
3. Распакуйте в новую папку, например `C:\QStudy`.
4. Запустите локальный, LAN- или интернет-стартер. Среда установится автоматически; данные уже находятся на месте.
5. Войдите тем же аккаунтом и паролем, которые были на момент экспорта.

Архив уже содержит одну папку `QStudy` с учебным сайтом, игрой QBall, логотипами и пятью CMD-файлами. Открывайте папку, где лежат эти кнопки. Прежняя отдельная папка LumaBall и второй сервер не нужны. Полный ZIP исключает скачиваемые среды, `node_modules`, production-сборку и состояние процессов; при первом запуске на новом компьютере нужен интернет, свободное место и время для установки и сборки.

Для размещения у друга запускается одна серверная копия. Остальные участники открывают выданный хостом адрес сайта и `/qball` в браузере. Не запускайте у каждого собственную копию ради подключения: базы на разных компьютерах автоматически не объединяются. При интернет-запуске должен быть доступен входящий TCP 8080; наличие ZIP и успешная локальная сборка не заменяют настройки роутера/провайдера. Точная проверка и проброс описаны в [инструкции для хоста](friend-hosting.md).

ZIP из GitHub содержит только код. Если он уже установлен, загрузите полную или обычную резервную копию в админке, проверьте предпросмотр и примените её. Текущие процессы останавливаются перед заменой базы: SQLite не заменяется под работающим сервером. После завершения нужен новый вход. Повторные старты этот импорт не повторяют.

Можно скопировать папку вручную после остановки сайта в админке: код, выбранную базу, uploads и соответствующий `.env`. Не исключайте настоящее хранилище, даже если пропускаете `.local/`, `node_modules/` и окружения. Пересоздание среды Python на новом диске не пересоздаёт базу.

Если очень старые записи содержат абсолютные пути к документам прежнего компьютера, используйте полный экспорт через админку: он проверяет документы и приводит пути в снимке к переносимому виду. Простая копия папки не исправляет произвольные устаревшие ссылки.

## Управление

Чтобы остановить QStudy вместе с игрой, дважды щёлкните **`Stop-QStudy.cmd`** на компьютере хоста. Дождитесь сообщения об остановке. Окно показывает результат и не закрывается само. Файл работает без интернета и не устанавливает зависимости. Процессы завершают текущие операции с базой; аккаунты, загруженные файлы, логотипы и настройки остаются на месте. Повторное нажатие безопасно.

Из браузера администратор может открыть **«Администрирование» → «Работа сайта» → «Остановить сайт»** и подтвердить остановку. Это выключает сайт для всех пользователей, включая игру. Снова включить сайт можно нужным `Start-QStudy*.cmd` на хосте; выключенный сервер не может включить себя из браузера. При запуске вручную без штатного стартера панель объясняет, как остановить его на хосте.

Остановка закрывает только принадлежащие этой установке процессы и её собственное правило брандмауэра/автоматический проброс. Правило проброса, добавленное вручную владельцем роутера, удаляется вручную; после остановки сайт через него не отвечает. Закрытие браузера или окна стартера оставляет сайт работать.

В «Системе» администратор изменяет параметры почты/ИИ, скачивает проект, загружает копии, перезапускает и останавливает сайт. Поля секретов показывают только наличие значения; пустое поле оставляет прежний секрет. После изменения параметров, читаемых при запуске, перезапустите сайт.

При старом способе запуска экспорт и проверка ZIP доступны, но применение/перезапуск требуют один раз запустить обновлённый стартер. Права администратора приложения не означают права администратора Windows.

Обычная автоматическая копия содержит базу и uploads. Полный переносимый проект дополнительно содержит код и настройки. Исходные `local-documents/`, сторонние папки и личные служебные файлы вне данных приложения не входят в экспорт: передайте их отдельно, если нужны.

## Обновление кода

Скачайте резервную копию, остановите сайт в админке, обновите исходники, сохраняя базу, uploads и `.env`, и запустите прежний стартер. Он проверит зависимости и сборку. GitHub не хранит вашу рабочую базу и не служит её резервной копией.

Не распаковывайте приватный ZIP поверх более новой рабочей установки: для изменения данных используйте явный импорт в админке. Если программный код изменился после передачи архива, импорт копии не откатывает этот код.

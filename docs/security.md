# Хранение данных и доступ

GitHub хранит исходный код и стандартные ресурсы интерфейса. Репозиторий `Ex-bex/QStudy` закрытый; доступ предоставляется только владельцем. Закрытый репозиторий не заменяет проверку прав внутри приложения.

В Git исключены `backend/.env`, другие рабочие `.env.*`, базы SQLite и их служебные файлы, `backend/uploads/`, `.backups/`, `.local/` и `local-documents/`. Файлы `.env.example` содержат только шаблон настроек. Не используйте `git add -f` для служебных данных.

Загруженные администратором логотипы сохраняются как нормализованные PNG в таблице `branding_assets`. Они включены в резервную копию базы и сохраняются после переноса `backend/studyhub.db`. Эти изображения доступны посетителям сайта; для загрузки подходят только публичные логотипы. Исходные имена и метаданные PNG удаляются. Изменение и сброс доступны только администратору и записываются в журнал действий.

Учебные оригиналы находятся в `local-documents/`: их следует копировать отдельно при переносе через Git. Обычное копирование всей папки проекта сохраняет их. Резервные копии приложения включают опубликованные загрузки, но не являются копией всех файлов этой папки.

Первоначальный локальный файл с доступом администратора, если он был создан, перенесён в `.local/credentials/initial-admin.txt`. Не публикуйте его. Для восстановления используйте штатный поток восстановления пароля или локальную команду администратора из README.

CI использует отдельные тестовые данные и токен только с правом чтения исходников; рабочие секреты туда не передаются. Исходные пользовательские документы в CI отсутствуют: проверки форматов и импорта работают с тестовыми данными, а сверка конкретного оригинала выполняется локально, когда файл присутствует.

Windows-команды запуска используют localhost или явно включённую локальную сеть. Для публичного сервера предусмотрен отдельный производственный запуск Next.js и FastAPI через Docker Compose и HTTPS-прокси Caddy: [инструкция](deployment.md). Публичными становятся только порты 80/443; база, загрузки, конфигурация и backend не публикуются как статические файлы. Нужны реально настроенные сервер, DNS-домен и доступ снаружи; подготовленные файлы развёртывания сами по себе ещё не означают, что сайт размещён в интернете.

Перед запуском задайте доверенный `PUBLIC_BASE_URL` с HTTPS, настройте SMTP для самостоятельного восстановления, при необходимости закройте регистрацию и создайте административный аккаунт. Секрет `BFF_PROXY_SECRET` должен совпадать у frontend и backend: он используется для доверенной передачи клиентского IP от закрытого шлюза; forwarded-заголовки произвольного посетителя не дают такого доверия. Не открывайте frontend или backend в обход входного прокси и не размещайте папки данных в публичном каталоге веб-сервера. Копии хранятся отдельно от образов приложения; переносите готовые архивы также на отдельный защищённый носитель.

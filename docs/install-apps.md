# Установка приложений QForce

У проектов есть отдельные PWA: QForce, QStudy, QBall, QCareer, QTests, QMessage, QControl и Q-ID. Каталог и краткая инструкция доступны на `/apps`. На страницах проектов и внутри рабочих пространств есть кнопка «Установить».

Откройте нужный проект, а затем устанавливайте его. У каждого свой стабильный идентификатор, название, значок и начальная страница. QStudy открывает «Обзор», QBall — комнаты, QMessage — переписки, QTests — библиотеку, QCareer — личную траекторию. Общий Q-ID сохраняется; установка не выдаёт права администратора. QControl по-прежнему проверяет роль на сервере.

Если переход между проектами произошёл без перезагрузки, кнопка сначала предложит подготовить установку выбранного проекта. Это обновляет документ и исключает установку соседнего приложения по старому приглашению браузера.

## Телефон и компьютер

- Android: Chrome или Samsung Internet → нужный проект → «Установить» на сайте или в меню браузера → подтвердить. Конкретный вид установки зависит от браузера, устройства и доступности его служб.
- iPhone/iPad: Safari → нужный проект → «Поделиться» → «На экран „Домой“» → «Добавить». Если доступен переключатель «Открывать как веб-приложение», включите его. Отдельное системное приглашение Android на iOS не используется.
- Windows/macOS/Linux: Chrome или Edge → нужный проект → «Установить» или значок установки в адресной строке.

Ссылки из встроенного браузера Telegram и подобных приложений откройте во внешнем браузере. Если уже создан обычный ярлык, удалите его и установите приложение. Повторно создавать аккаунт не нужно; на отдельных платформах может потребоваться заново войти в Q-ID в окне приложения.

## Почему по HTTP есть ярлык, но нет установки

Для полноценной установки нужен HTTPS с сертификатом, которому доверяет телефон. Браузер допускает HTTP только для `localhost` и loopback на самом устройстве. Адрес `http://94.125.99.135:8080`, адрес компьютера в Wi-Fi и локальный HTTP в телефоне не получают это исключение.

PWA-файлы не могут отключить это требование. На обычном HTTP кнопка объясняет причину. Сайт и текущий режим запуска остаются доступны; автоматического изменения портов, адреса, сертификатов и сетевых настроек нет.

Владельцу хоста нужно выбрать защищённый публичный адрес и настроить HTTPS перед QStudy. В проекте есть конфигурация `deployment/Caddyfile` для домена с автоматическим сертификатом и отдельная `deployment/Caddyfile.http` для прежнего HTTP-режима. Само наличие этих файлов не включает HTTPS в действующем нативном запуске. Для домена потребуются DNS-запись на белый IP, доступные внешние порты 80/443, reverse proxy к действующему приложению и соответствующий публичный HTTPS-адрес в настройках запуска/приложения. Установка на телефоне проверяется именно по итоговому HTTPS-адресу, а не по `127.0.0.1` на компьютере разработчика.

Ручная настройка браузера, которая объявляет небезопасный IP доверенным, и самоподписанный недоверенный сертификат не являются способом развёртывания для пользователей.

## Обновления и данные

Веб-приложения используют тот же сервер и базу. Для обычной работы нужен интернет и включённый хост. В service worker кэшируется только общий экран отсутствия сети. Личные страницы, API, документы, сообщения, фотографии переписки и результаты тестов не складываются в общий офлайн-кэш. Резервные копии и перенос выполняются через QControl как раньше.

Логотипы установленных приложений формируются в PNG 180/192/512 из текущих логотипов проектов. Изображения имеют безопасные поля для системной маски. После замены логотипа в QControl браузер может обновить установленный значок с задержкой; переустановка ускоряет его обновление. Идентификаторы приложений при этом не меняются.

Техническая проверка: `/apps/qstudy/manifest.webmanifest`, `/apps/qstudy/icon/192.png`, `/apps/qstudy/icon/512.png` должны открываться без авторизации; `/sw.js` должен возвращать JavaScript без долгого кэширования. Все маршруты обслуживаются через текущий сайт и порт, дополнительные порты для PWA не нужны.

Официальные требования: [MDN — установка PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), [web.dev — установка на разных устройствах](https://web.dev/learn/pwa/installation).

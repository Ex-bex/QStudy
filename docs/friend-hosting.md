# Windows-хост: белый IP и порт 8080

Адрес сайта — `http://БЕЛЫЙ_IP:8080`. Домен, сертификат, Cloudflare, VPS, Docker и WSL для нового запуска не требуются. Нужны включённый Windows-компьютер, публичный IPv4, разрешённый входящий TCP 8080 и проброс роутера.

## Первый запуск без команд

1. Получите приватный ZIP через **админку → Система → Скачать проект со всеми данными**. ZIP из GitHub содержит только исходники.
2. Распакуйте в обычную папку, например `C:\QStudy`. Не запускайте файлы внутри ZIP.
3. Дважды щёлкните **Start-QStudy-Internet.cmd**. Он проверит Python, Node.js и библиотеки, подготовит сборку и откроет существующую базу.
4. Разрешите запрос Windows для правила QStudy TCP 8080 под тем же Windows-аккаунтом. Брандмауэр целиком не отключается; порт API не открывается.
5. Дождитесь адреса и браузера. Аккаунты и пароли прежние; нового администратора при наличии аккаунта создавать не нужно.
6. Проверьте адрес на телефоне через мобильную сеть с выключенными Wi-Fi и VPN.

Повторный запуск использует ту же базу и не восстанавливает ZIP. Управление почтой, ИИ, аккаунтами, копиями и перезапуском находится в админке.

## Ручное правило роутера, если UPnP недоступен

Окно покажет реальные адреса. Копия инструкции — `.local/launcher/router-instructions.txt`.

1. Откройте показанный адрес роутера и войдите самостоятельно.
2. Найдите **NAT / Port Forwarding / Переадресация портов / Виртуальные серверы**.
3. Добавьте одно включённое правило:

| Поле | Значение |
| --- | --- |
| Название | QStudy |
| Внешний порт | **8080** |
| Внутренний порт | **8080** |
| Протокол | **TCP** |
| Внутренний IP / IP устройства | **LAN-IP Windows-компьютера из окна запуска** |
| Удалённый источник | Any / любой |

4. Закрепите LAN-IP за этим компьютером в DHCP / Address Reservation.
5. Сохраните правило и проверьте сайт через мобильный интернет. Если правило с таким назначением уже существует, второе не нужно.

**Белый IP не указывается во внутреннем IP правила.** Для `http://94.125.99.135:8080` нужен именно LAN-IP компьютера друга, определённый на этом компьютере. IP ноутбука разработчика не подходит.

## Если снаружи не открывается

- Проверьте готовность сайта в окне стартера и занятость 8080. Стартер не останавливает чужие процессы и не меняет порт на 8081.
- В роутере сравните WAN IPv4 с внешним IP из окна. WAN вида `10.x`, `172.16–31.x`, `192.168.x` или `100.64–127.x` означает другой NAT/CGNAT. Нужен второй проброс на собственном роутере либо белый IPv4 у провайдера.
- Уточните у провайдера: «Нужен публичный IPv4 на WAN роутера и разрешённые входящие TCP-подключения на 8080». Внешний IP в сервисе проверки сам по себе не доказывает белый IP на WAN вашего роутера.
- Отключите VPN для первичной проверки. Некоторые роутеры не открывают свой внешний IP из домашней сети: проверяйте с мобильного интернета.
- Если пароль роутера изменён провайдером, запросите доступ или настройку проброса. QStudy не может обойти пароль роутера.
- Интернет-режим принимает настроенный адрес сайта. Произвольный другой Host может блокироваться защитой.

Готовность приложения и UPnP-правило не подтверждают доступ снаружи. Нужна проверка с другого подключения.

## Постоянная работа

Не выключайте компьютер и отключите сон при питании от сети. После перезагрузки Windows снова запустите ту же кнопку. При динамическом белом IP адрес может измениться: стартер определит его заново. Письма восстановления, отправленные со старым адресом, нужно запросить повторно.

HTTP без сертификата не шифрует пароли, документы и сессии. Проверки прав, HttpOnly, SameSite и Origin остаются, но не заменяют TLS. Микрофон браузера на публичном HTTP может быть недоступен; можно загрузить аудиофайл. Отдельный HTTPS-вариант: [развёртывание](deployment.md).

Приватный ZIP и `.env` не публикуйте. [Сохранение данных, импорт и обновления](startup.md).

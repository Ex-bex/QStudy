# Передача QStudy другу: Windows, белый IPv4 и порт

Эта инструкция предназначена владельцу Windows-компьютера, который будет обслуживать QStudy. Адрес сайта — **`http://БЕЛЫЙ_IPV4:ПОРТ`**. Схема: **интернет → роутер друга → HTTP-прокси Caddy → QStudy в Docker**. Домен, сертификат, Cloudflare и VPS не нужны. Требуются публичный IPv4 без CGNAT, автоматический или ручной проброс портов и разрешённый провайдером входящий TCP на выбранном порту.

В этом режиме HTTP действительно не шифрует соединение браузера с сайтом: пароли, сессии, документы и ссылки восстановления передаются без TLS. Роли, проверка прав, ограничения запросов, `HttpOnly`, `SameSite=Strict` и проверка Origin/Host продолжают работать, но не заменяют шифрование. Публичный HTTP включается явно при подготовке; HTTPS со своим доменом остаётся отдельным вариантом в [инструкции развёртывания](deployment.md).

Есть ограничения браузера: запись с микрофона через `getUserMedia` требует безопасного контекста и на обычном публичном HTTP недоступна. Используйте текстовый ввод либо загрузите готовое аудио в разделе файлов. Кнопка копирования также может быть недоступна — выделите и скопируйте текст вручную. [Микрофон](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [буфер обмена](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText).

Подготовка файлов сама по себе не публикует сайт. Для обычного запуска используйте кнопку ниже: она последовательно готовит приложение и аккаунты, настраивает сеть и запускает входной прокси. Первичную установку Docker/WSL и недоступную автоматизации настройку роутера выполняет владелец хоста. Проверку из интернета выполните с телефона при выключенном Wi-Fi.

Ниже `PUBLIC_IPV4`, `your-admin@example.org`, `192.168.1.50` и имя ZIP — примеры или заглушки. Вместо **`PUBLIC_IPV4`** в каждой команде укажите настоящий белый IPv4 друга; буквальная заглушка не принимается. Все команды PowerShell выполняются из корня проекта, например `C:\QStudy`. Настоящие настройки и секреты задавайте на компьютере друга, не в Git.

## Быстрый запуск одной кнопкой

На **Windows-компьютере друга, подключённом к его белому IP**, получите актуальную версию проекта. Один раз установите Docker Desktop, примите его условия, подготовьте WSL 2 и выберите Linux containers; подробно это описано в разделе 2. Наличие установленного Docker без готового Linux Engine недостаточно. Затем дважды нажмите **`Start-QStudy-Internet.cmd`** либо выполните:

```powershell
Set-Location 'C:\QStudy'
.\Start-QStudy-Internet.cmd
```

При первой настройке кнопка определяет внешний IPv4, выбирает свободный TCP-порт **8080–8179** и сохраняет адрес. При повторном запуске используются сохранённые IP и порт, в том числе `3000`, если он был явно настроен для production HTTP. Кнопка открывает уже установленный Docker Desktop и до трёх минут ждёт локальный Linux Engine; сама Docker/WSL не устанавливает, не принимает условия и не перезагружает Windows.

Образы собираются при первом запуске, изменении исходников или отсутствии необходимых образов. Для неизменившегося проекта повторный запуск использует готовые образы; состояние сборки связано с этим компьютером и папкой. Для принудительной сборки выполните `Start-QStudy-Internet.cmd -Rebuild`. Библиотеки, Python, Node.js и OCR приложения устанавливаются внутри образов.

Перед публикацией запускаются только приватные сервисы. Если в базе нет активного администратора, вводятся email и новый пароль дважды скрыто. Если администратор уже есть, повторного запроса и сброса аккаунтов нет. По умолчанию самостоятельная регистрация закрыта. SMTP и ключ ИИ настройте отдельно через мастер `Setup-QStudy-Host.cmd` или поля приватного `deployment/.env`, описанные ниже: новая кнопка не запрашивает эти секреты.

Если папка скопирована вместе с `backend/studyhub.db`, а production-базы ещё нет, запуск остановится, чтобы не создать пустой сайт вместо ваших данных. Создайте штатную копию на старой установке, поместите ZIP в `deployment/data/backups/` и выполните **один раз**:

```powershell
.\Start-QStudy-Internet.cmd -Archive 'qstudy-20261011-120000-abcd1234.zip'
```

Принимается только имя архива из указанной папки. Восстановление выполняется с `-NoPublish` до проверки администратора и публичного запуска; существующий административный аккаунт и его пароль сохраняются. Следующие запуски выполняйте без `-Archive`, чтобы не восстанавливать копию повторно. Для намеренно отдельной пустой установки есть `-NewInstallation`; файлы локальной базы и загрузок не удаляются. `-Archive` и `-NewInstallation` вместе не используются. Подробный перенос описан в разделе 5.

Далее кнопка проверяет сеть, запрашивает UAC для своего правила Windows Firewall и пытается пробросить выбранный TCP-порт через UPnP/NAT-PMP. Подтверждайте UAC под **тем же Windows-аккаунтом**, который запустил QStudy. Если автоматизация роутера недоступна, настройте один раз правило **внешний TCP PORT → закреплённый LAN-IP этого хоста:PORT**, затем повторите:

```powershell
.\Start-QStudy-Internet.cmd -ManualForwarding
```

Этот флаг использует уже созданный ручной проброс; он не создаёт белый IP, не отменяет CGNAT и не открывает запрет у провайдера. Неудача автоматизации выводит этап и причину, а также команды диагностики.

После готовности контейнеров проверяются `/api/health` и главная через `127.0.0.1:PORT` с точным публичным Host. Проверка не зависит от NAT loopback роутера и не ослабляет проверку адреса сайта. Затем браузер открывает сохранённый `http://IP:PORT`. Сообщение «QStudy работает на хосте» подтверждает локальную работу; откройте этот адрес **с телефона с выключенным Wi-Fi и VPN**, чтобы подтвердить вход из интернета. Если телефон открывает сайт, а браузер хоста нет, проверьте NAT loopback в разделе 8.

Параметры этой кнопки:

| Параметр | Назначение |
| --- | --- |
| `-PublicIP 'PUBLIC_IPV4' -Port 8080` | Явный IP и порт при первой настройке; для существующей установки принимаются только совпадающие значения |
| `-RouterWanIPv4 'PUBLIC_IPV4'` | Известный WAN роутера для диагностики отсутствия промежуточной сети |
| `-AdminEmail 'your-admin@example.org'` | Email первого администратора, только если активного администратора ещё нет |
| `-Archive 'ИМЯ.zip'` | Восстановить штатную копию из `deployment/data/backups/` до публикации |
| `-NewInstallation` | Явно создать отдельную пустую production-установку при наличии локальных данных |
| `-ManualForwarding` | Использовать заранее настроенный ручной проброс вместо UPnP/NAT-PMP |
| `-Rebuild` | Принудительно собрать образы заново |
| `-EnableAutostart` | После успешного запуска включить запуск контейнеров при входе этого Windows-пользователя |
| `-NoBrowser`, `-NoPause` | Не открывать браузер; не ждать Enter в конце |

Сохранённый HTTPS-режим или другой IP/порт эта кнопка не меняет. Порядок согласованной смены адреса находится в разделе 10. Далее описаны диагностика и прежний поэтапный мастер, который остаётся доступен для SMTP, подготовки, переноса и обслуживания.

## 1. Подтвердите белый IPv4

Друг должен уточнить у провайдера:

> На компьютере будет веб-сайт. Нужен публичный IPv4 без CGNAT и разрешённые входящие соединения TCP на выбранном порту, например 8080. Адрес статический или динамический? Кто может настроить проброс на вашем роутере?

Статический публичный IPv4 удобнее: ссылка на сайт остаётся постоянной. Белый адрес может быть и динамическим — порядок действий при его смене описан ниже.

Сравните **WAN / Internet IPv4** в панели роутера с внешним адресом, найденным диагностикой на хосте:

```powershell
Set-Location 'C:\QStudy'
.\Test-QStudy-HomeNetwork.cmd -HttpPort 8080
```

Если WAN известен, передайте его диагностике:

```powershell
.\Test-QStudy-HomeNetwork.cmd -RouterWanIPv4 'PUBLIC_IPV4' -HttpPort 8080
```

Адрес, показанный внешним сервисом, сам по себе не доказывает отсутствие CGNAT. Приватный WAN `10.*`, `172.16.*–172.31.*`, `192.168.*` или диапазон `100.64.*–100.127.*` означает промежуточную сеть. При двух собственных роутерах нужен согласованный проброс на обоих. [Разъяснение TP-Link](https://www.tp-link.com/ph/support/faq/785/), [диапазон CGNAT](https://www.rfc-editor.org/info/rfc6598/).

Если провайдер изменил пароль панели, попросите клиентский доступ либо настройку проброса. Сброс устройства может стереть параметры подключения. Удалённое управление роутером из интернета включать не требуется. [Рекомендации TP-Link для оборудования провайдера](https://www.tp-link.com/us/support/faq/4370/).

## 2. Подготовьте Windows и Docker

Используйте поддерживаемую 64-битную Windows, актуальный Docker Desktop с Linux containers и WSL 2. Проверьте аппаратную виртуализацию, доступные обновления и требования перед установкой. Для сборки и OCR желательно 16 ГБ RAM и свободное место для образов, документов и копий. [Требования Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/).

Подключите компьютер к роутеру кабелем Ethernet, если возможно. Если WSL отсутствует, выполните из PowerShell администратора:

```powershell
wsl --install --no-distribution
wsl --update
```

После требуемой перезагрузки войдите в тот же Windows-аккаунт. Отдельная Ubuntu не обязательна: Docker Desktop использует собственную Linux-среду. [Команды WSL](https://learn.microsoft.com/en-us/windows/wsl/basic-commands).

Установите и откройте Docker Desktop, примите его условия и дождитесь работающего Linux Engine. Проверьте:

```powershell
docker version
docker compose version
```

У `docker version` должны отображаться Client **и Server**. Наличие установленной программы без работающего Engine недостаточно.

Node.js, Python приложения, библиотеки и Tesseract OCR устанавливаются внутри образов при сборке. Мастер проверяет среду; установка системных компонентов, первый запуск Docker или перезагрузка Windows могут требовать действий владельца.

## 3. Получите исходники из закрытого GitHub

Репозиторий [Ex-bex/QStudy](https://github.com/Ex-bex/QStudy) остаётся приватным. Доступ посетителей к сайту не требует открытия исходников.

Передайте другу архив только исходников либо предоставьте хосту доступ чтения Git. Для отдельного серверного компьютера подходит deploy key без `Allow write access`: закрытый ключ остаётся на хосте, публичная часть добавляется в GitHub владельцем репозитория. Пароль GitHub и токен в URL клонирования не нужны. [Настройка deploy key](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys).

После настройки Git/SSH и проверки ключа сервера GitHub:

```powershell
git clone --branch main git@github.com:Ex-bex/QStudy.git 'C:\QStudy'
Set-Location 'C:\QStudy'
```

Не перезаписывайте существующую папку с данными ради повторного клонирования. Архив исходников не включает `.env`, `.local`, SQLite-базу, загрузки, резервные копии, `.venv`, `node_modules` и `.next`. Пользовательские данные передают отдельно штатной копией.

## 4. Подготовьте HTTP-конфигурацию

На новом хосте:

```powershell
Set-Location 'C:\QStudy'
.\Setup-QStudy-Host.cmd -PublicIP 'PUBLIC_IPV4' -Port 8080 -Prepare
```

Мастер создаёт приватную production-конфигурацию, предлагает настроить SMTP и ключ ИИ, проверяет среду и собирает приложение. `-Prepare` запускает только внутренние backend/frontend для подготовки аккаунтов или восстановления. Публичный прокси и внешние порты ещё не запускаются. Без `-Prepare` или `-Start` мастер выполняет настройку и проверки без сборки и публикации. Параметры `-Domain` и `-Email` для HTTP не нужны.

Если не указать `-PublicIP`, мастер предложит найденный через ipify внешний адрес как значение по умолчанию. Сверьте его с WAN роутера: автоматическое определение не устраняет CGNAT. Если не указать `-Port` либо задать `-Port 0`, при первой настройке выбирается свободный порт из диапазона **8080–8179**. Выбранное значение выводится и сохраняется; повторный запуск использует его. Пробрасывайте именно показанный порт. Сам автоподбор и `-Prepare` не меняют роутер; сетевые изменения выполняются при отдельной команде `enable` либо при `-Start`.

Дополнительные параметры:

| Параметр | Назначение |
| --- | --- |
| `-Prepare` | Собрать образы и запустить только приватные сервисы |
| `-Start` | Настроить правило Windows Firewall и автоматический проброс, затем запустить публичный сайт |
| `-ManualForwarding` | Вместе с `-Start` открыть правило Windows Firewall и использовать уже настроенный вручную проброс |
| `-EnableAutostart` | Вместе с `-Start` включить запуск при входе текущего Windows-пользователя |
| `-SkipPrivateSettings` | Не повторять вопросы SMTP и ключа ИИ; сохранённые значения остаются |
| `-NoPause` | Не ждать нажатия клавиши в конце |

`-Prepare` и `-Start` используются отдельно. Существующий файл `deployment/.env` не заменяется новыми секретами. Если в нём ранее был HTTPS-домен или другой IP/порт, мастер откажется молча менять схему: остановите сайт, сохраните копию конфигурации и согласованно измените перечисленные ниже поля вручную.

Вариант без вопросов мастера, для нового хоста:

```powershell
.\Manage-QStudy-Internet.cmd init-http -PublicIP 'PUBLIC_IPV4' -Port 8080
```

После него заполните приватные настройки и выполните `prepare`.

### Настройки `deployment/.env`

| Поле | Значение |
| --- | --- |
| `QSTUDY_HOST_MODE` | `http` |
| `QSTUDY_PUBLIC_IP` | Настоящий белый IPv4 друга |
| `QSTUDY_HTTP_PORT` | Выбранный внешний и внутренний TCP-порт, например `8080` |
| `ALLOW_PUBLIC_HTTP` | `true`, явное разрешение публичного HTTP |
| `PUBLIC_BASE_URL` | Ровно `http://IP:PORT`, без пути и завершающего `/` |
| `REGISTRATION_ENABLED` | `false` до проверки администратора и данных |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | Ключ ИИ и доступная ему модель |
| `RECOVERY_DELIVERY` | `smtp`, если почта настроена; иначе `disabled` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY` | Почтовый сервер, порт и `starttls` либо `ssl` |
| `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` | Аккаунт, закрытый пароль и отправитель QStudy |

`QSTUDY_DOMAIN` и `ACME_EMAIL` в HTTP-шаблоне остаются неиспользуемыми заглушками; реальный домен и email для сертификата не вводятся. Менеджер автоматически выбирает `deployment/compose.http.yml`. Caddy обслуживает обычный HTTP без получения сертификата и перенаправления на HTTPS; frontend, backend, база и документы остаются во внутренних сетях контейнеров.

Для Gmail используется пароль приложения; настройки описаны в [инструкции почты](mail.md). Соединение сервера с SMTP по-прежнему проверяет TLS, даже когда сам сайт работает по HTTP. SMTP и ключ ИИ введите скрытым вводом мастера либо в приватном редакторе `deployment/.env`.

При ручном редактировании следуйте одинарным кавычкам шаблона. Не запускайте `.env` как скрипт и не печатайте раскрытый `docker compose config`, который содержит секреты. Сохраните созданные случайные `SECRET_KEY` и `BFF_PROXY_SECRET`; не заменяйте файл целиком старым `backend/.env`.

Проверка подготовленной конфигурации и Docker:

```powershell
.\Manage-QStudy-Internet.cmd check -Offline
```

## 5. Подготовьте данные и администратора

Если мастер запускался без `-Prepare`, сначала выполните:

```powershell
.\Manage-QStudy-Internet.cmd prepare
```

Команда собирает образы, проверяет Caddy и поднимает внутренние backend/frontend. Если публичный Caddy этой установки уже работает, сначала штатно остановите сайт: частная подготовка не смешивается с публикацией.

### Перенос существующей установки

1. На старом компьютере создайте в админке готовую штатную резервную копию и скачайте ZIP. В ней находятся согласованная база, документы и логотипы.
2. Перед окончательной копией завершите изменения на старом хосте и остановите его. После переключения работайте только с новым хостом, чтобы записи не разошлись.
3. Передайте ZIP приватно либо лично на защищённом носителе. Сохраните исходное имя в `C:\QStudy\deployment\data\backups\` до публикации.
4. Проверьте и восстановите настоящее имя архива:

```powershell
.\Manage-QStudy-Internet.cmd verify -Archive 'qstudy-20261011-120000-abcd1234.zip'
.\Manage-QStudy-Internet.cmd restore -Archive 'qstudy-20261011-120000-abcd1234.zip' -NoPublish
```

`verify` проверяет структуру, контрольные суммы и SQLite. `restore -NoPublish` останавливает сервисы, сохраняет прежнее состояние, восстанавливает базу с файлами и запускает только внутренние backend/frontend. Caddy остаётся остановленным. При ошибке сервисы остаются остановлены; ручная распаковка поверх работающей базы не нужна. Принимается только имя готового архива из `deployment/data/backups/`, не произвольный путь.

5. SMTP и ключ ИИ настройте отдельно: `.env` не входит в архив. Нужные оригиналы из `local-documents/`, отсутствующие в копии, передайте отдельно приватным способом.

Переносятся аккаунты, группа, расписание, силабусы, недели, работы, личные материалы и задания ИИ. Пароль существующего администратора сохраняется; прежние сессии и ссылки восстановления отзываются, незавершённые задания возвращаются в очередь. Не создавайте временные рабочие аккаунты до восстановления и не переносите одну базу без загрузок.

### Новая установка

После `prepare` создайте администратора:

```powershell
.\Manage-QStudy-Internet.cmd admin -Email 'your-admin@example.org' -Name 'Администратор'
```

Пароль вводится дважды скрыто. Если email уже существует, команда назначает роль администратора, **меняет пароль и отзывает сессии**. После переноса использовать её для прежнего администратора не требуется, если пароль менять не нужно. До запуска Caddy вход через браузер ещё не опубликован.

## 6. Закрепите LAN-адрес и настройте доступ из сети

Посмотрите адрес активного Ethernet/Wi-Fi:

```powershell
Get-NetIPConfiguration
Get-NetConnectionProfile
```

В роутере создайте **DHCP reservation / Статическую аренду** для сетевой карты Windows-хоста, например `192.168.1.50`. Для проброса нужен адрес Windows-компьютера, а не WSL, Docker или VPN.

После подготовки аккаунтов или восстановления данных попробуйте автоматическую настройку:

```powershell
.\Manage-QStudy-PublicAccess.cmd enable
.\Manage-QStudy-PublicAccess.cmd status
```

Команда читает выбранные IP и порт из приватной HTTP-конфигурации `deployment/.env`. Windows запросит UAC для создания одного входящего правила TCP на этот порт. До и после UAC должна использоваться **одна Windows-учётная запись администратора хоста**. Если сейчас используется обычная учётная запись, войдите в учётную запись администратора и выполняйте настройку там; ввод данных другой учётной записи в окне UAC не подходит для владения настройками и задачей продления.

QStudy определяет активный LAN-маршрут и пытается добавить соответствующий проброс через UPnP или NAT-PMP. Проверяются владелец локального порта, собственные правила Windows и описание проброса UPnP. **Зарезервируйте выбранный внешний и внутренний TCP-порт только для QStudy**: протокол NAT-PMP не предоставляет список пробросов и их описание, поэтому наличие чужого проброса нельзя независимо проверить. Дополнительные службы UPnP и удалённое управление роутером команда не включает.

При успешном автоматическом пробросе создаётся отдельная задача текущего пользователя: после входа и каждые 15 минут она продлевает аренду порта. Сайт и Docker запускаются другой задачей, описанной ниже. Продление проверяет сохранённые настройки и сетевой маршрут; при изменении адреса или маршрута повторите `enable` после согласованного обновления конфигурации.

Если роутер не поддерживает автоматический проброс, не разрешает его либо возвращает конфликт порта, команда сообщает `status='manual_required'` и завершается с кодом 2. Поле `mapping_status` содержит точную причину ответа роутера. Созданное правило Windows остаётся для ручной настройки.

При известном приватном/CGNAT WAN или несовпадении с настроенным публичным IP сохраняются `router_public_ip` и `provider_action_required=true`; состояние сообщает о необходимости настройки у провайдера. Новое правило firewall при этом не открывается. Команда `manual` тоже отклоняет известный неподходящий WAN: сначала разрешите проблему адресации с провайдером. Если WAN подходит, но автоматизация роутера недоступна, выполните:

```powershell
.\Manage-QStudy-PublicAccess.cmd manual
```

Команда открывает только правило Windows и показывает точные параметры для **Port Forwarding / Virtual Servers** в роутере:

| Внешний порт | Протокол | Внутренний адрес | Внутренний порт |
| --- | --- | --- | --- |
| 8080, либо фактически выбранный | TCP | Закреплённый LAN-адрес хоста | Тот же порт, например 8080 |

Внешний и внутренний порт должны совпадать с `QSTUDY_HTTP_PORT`. Дополнительно открывать TCP 80/443 или UDP не требуется: разрешите только выбранный TCP-порт. [Проброс на TP-Link](https://www.tp-link.com/us/support/faq/1379/).

Отдельное ручное правило в `wf.msc` для этого порта после `enable` или `manual` не требуется. Учтите также сторонний firewall и сетевую работу Docker Desktop. [Сеть Docker Desktop](https://docs.docker.com/desktop/features/networking/).

Не включайте DMZ и не публикуйте порт локального frontend, backend `8000`, Docker API или RDP. Только Caddy получает вход посетителей. Если production явно настроен на `QSTUDY_HTTP_PORT='3000'`, пробрасывается именно TCP 3000 входного Caddy; это отдельный режим от `Start-QStudy.cmd`. Белый IP и отсутствие CGNAT по-прежнему необходимы: UPnP/NAT-PMP не отменяют ограничения провайдера. `status` показывает сохранённое состояние, но не доказывает доступность с другого подключения. Домен, DNS-записи и DDNS для адреса `IP:PORT` не настраиваются.

Для отключения созданного QStudy сетевого доступа:

```powershell
.\Manage-QStudy-PublicAccess.cmd disable
```

Удаляются только собственное правило Windows, задача продления и подтверждённый автоматический проброс этой установки. Ручной проброс удалите самостоятельно в роутере. Сайт останавливается отдельно командой `Manage-QStudy-Internet.cmd stop`.

Если изменился маршрут и проброс не удалось удалить, сохраняется `router_cleanup_pending`. Вернитесь в исходную сеть и повторите `disable`, либо удалите именно указанный проброс вручную в прежнем роутере. Когда подтверждено, что проброс удалён или его аренда истекла, очистите сохранённую запись:

```powershell
.\Manage-QStudy-PublicAccess.cmd -Action disable -RouterCleanupConfirmed
```

Этот флаг означает ваше подтверждение удаления/истечения аренды, а не проверку роутера. Он очищает запись после отключения локального доступа и не отправляет команды роутеру; после этого можно настроить новую сеть.

## 7. Запустите публичный HTTP-сайт

Основной запуск — `Start-QStudy-Internet.cmd` из быстрого раздела. Для прежнего поэтапного варианта после подготовки данных запустите мастер:

```powershell
.\Setup-QStudy-Host.cmd -PublicIP 'PUBLIC_IPV4' -Port 8080 -Start -SkipPrivateSettings
```

Если выбран другой порт, укажите его. С `-Start` мастер автоматически вызывает сетевую настройку `enable`; Windows может запросить UAC. Если проброс выполнен вручную, используйте:

```powershell
.\Setup-QStudy-Host.cmd -PublicIP 'PUBLIC_IPV4' -Port 8080 -Start -SkipPrivateSettings -ManualForwarding
```

Мастер сопоставляет заданный IP с текущим внешним адресом и результатом диагностики WAN; несовпадение адреса или известный приватный/CGNAT WAN блокируют запуск. DNS не требуется. При неизвестном WAN диагностика не может доказать отсутствие промежуточной сети — необходима внешняя проверка. `-ManualForwarding` означает, что правило на роутере уже настроено; этот параметр не доказывает доступность порта.

Повторный запуск уже настроенного сайта возможен напрямую:

```powershell
.\Manage-QStudy-Internet.cmd check
.\Manage-QStudy-Internet.cmd start
```

Запуск проверяет конфигурацию, сборку, Caddy, готовность сервисов и SMTP, если почта включена. Открывается сохранённый **`http://IP:PORT`**. Проба адреса с хоста проверяет QStudy; это ещё не доказательство доступности с другого подключения. При неудаче контейнеры могут остаться работающими для диагностики, но успешная публикация не объявляется. Уже восстановленные данные повторно распаковывать не нужно.

## 8. Проверьте с мобильного интернета

На телефоне отключите Wi-Fi и VPN. Откройте настоящий **`http://IP:PORT`**, сохранив `http://` и выбранный порт:

1. Главная и `/api/health` открываются; браузер может обозначать HTTP как незащищённое соединение. Сертификат и автоматический переход на HTTPS здесь отсутствуют.
2. Администратор входит и управляет общими данными. Студент видит свою группу и работает только со своими материалами.
3. На месте расписание, силабусы, недели, модули, работы, файлы и логотипы.
4. Восстановление отправляет настоящее письмо QStudy; ссылка ведёт на тот же IP и порт. `mail-check` проверяет SMTP без отправки и не заменяет получение письма.
5. ИИ отвечает с настроенным ключом, PDF-скан проходит OCR, фоновые задания сохраняются после штатного перезапуска.
6. В админке создаётся и скачивается готовая резервная копия.

Из домашней сети используйте **тот же публичный IP и порт**. Для этого роутер должен поддерживать NAT loopback / hairpin NAT. Если с мобильного интернета сайт работает, а дома нет, настройте эту функцию или обратитесь к владельцу роутера. Прямой переход на `http://192.168.1.50:PORT` в этой публичной конфигурации не подходит: проверка Host/Origin привязана к публичному адресу. Локальный сервер разработки и его LAN-команда — отдельный режим.

После проверки администратора и данных при необходимости включите `REGISTRATION_ENABLED='true'`, примените `start` и передайте студентам полный адрес. `localhost`, `127.0.0.1` и LAN-адрес не являются публичной ссылкой.

## 9. Включите автозапуск и резервные копии

В Docker Desktop включите **Settings → General → Start Docker Desktop when you sign in to your computer**, затем:

```powershell
.\Manage-QStudy-Internet.cmd install-autostart
```

Новая кнопка принимает `Start-QStudy-Internet.cmd -EnableAutostart`, прежний мастер — `-EnableAutostart` вместе с `-Start`. Включайте задачу после подготовки и проверки данных. Это автозапуск контейнеров; автоматическое продление проброса из команды `enable` имеет отдельную задачу и не запускает Docker.

Автозапуск действует **после входа того же Windows-пользователя**, не до экрана входа. После перезагрузки требуется войти в Windows и дождаться Docker. В настройках питания отключите сон при питании от сети; учтите закрытие крышки ноутбука. Питание, интернет и свободный диск нужны постоянно. [Настройки Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

| Действие | Команда |
| --- | --- |
| Запустить сайт с автоматической подготовкой и сетью | `.\Start-QStudy-Internet.cmd` |
| Пересобрать образы и запустить | `.\Start-QStudy-Internet.cmd -Rebuild` |
| Проверить контейнеры | `.\Manage-QStudy-Internet.cmd status` |
| Применить изменённый `.env` | `.\Manage-QStudy-Internet.cmd start` |
| Проверить SMTP без письма | `.\Manage-QStudy-Internet.cmd mail-check` |
| Создать копию | `.\Manage-QStudy-Internet.cmd backup` |
| Остановить сайт | `.\Manage-QStudy-Internet.cmd stop` |
| Отключить следующий автозапуск | `.\Manage-QStudy-Internet.cmd remove-autostart` |
| Проверить состояние сетевого доступа | `.\Manage-QStudy-PublicAccess.cmd status` |
| Отключить созданный сетевой доступ | `.\Manage-QStudy-PublicAccess.cmd disable` |

При установленной задаче следующий вход запускает QStudy снова даже после `stop`. Для длительной остановки выполните `remove-autostart`, затем `stop` и `Manage-QStudy-PublicAccess.cmd disable`; вручную созданный проброс удалите в роутере.

Автоматические копии включены: по умолчанию каждые 24 часа работы сохраняются последние 14 готовых архивов. Данные находятся в `deployment/data/backend/`, копии — в `deployment/data/backups/`. Регулярно сохраняйте дополнительную копию вне хоста; `.env` и закрытый Git-ключ храните отдельно. Проверку восстановления выполняйте на тестовой установке. Не удаляйте постоянные папки и Docker volumes и не запускайте `docker compose down -v` ради обновления.

## 10. Что делать при смене белого IP или порта

При динамическом IPv4 адрес сайта меняется вместе с адресом подключения. Без домена прежняя ссылка перестаёт работать; автоматического перенаправления с неё нет. Скрипт не заменяет публичный адрес молча при каждом запуске.

1. Выясните новый WAN и внешний IP диагностикой.
2. Остановите сайт штатной командой `stop` и выполните `Manage-QStudy-PublicAccess.cmd disable` до изменения настроек, чтобы удалить прежнее правило и автоматический проброс.
3. В приватном `deployment/.env` согласованно измените `QSTUDY_PUBLIC_IP` и `PUBLIC_BASE_URL`. При смене порта измените также `QSTUDY_HTTP_PORT`, правила роутера и брандмауэра; внешний и внутренний порт остаются одинаковыми.
4. Выполните `check`, затем `Manage-QStudy-PublicAccess.cmd enable` и `start`. Для ручного проброса используйте `manual` и обновите правило роутера. Проверьте новый адрес с мобильного интернета и сообщите его пользователям.
5. Для восстановления пароля запросите новые письма: прежние ссылки содержат старый адрес.

Повторный `init-http` намеренно сохраняет существующую конфигурацию и не меняет её IP/порт. Не удаляйте `.env` ради смены адреса: в нём находятся секреты и настройки почты/ИИ. Статический публичный IP избавляет от регулярной смены ссылок; DDNS и покупка домена в выбранной схеме не обязательны.

## 11. Обновляйте из приватного GitHub

Проверьте собственные изменения и создайте копию:

```powershell
Set-Location 'C:\QStudy'
git status --short
.\Manage-QStudy-Internet.cmd backup
git pull --ff-only origin main
.\Manage-QStudy-Internet.cmd update
```

Если исходники изменены, сначала сохраните и согласуйте правки. Вместо `update` можно запустить `Start-QStudy-Internet.cmd`: кнопка увидит изменение исходников и соберёт образы, затем выполнит локальную проверку HTTP без требования NAT loopback. `update` собирает полученный код, сохраняет постоянные данные и повторяет публичную проверку. При работающем backend менеджер также создаёт копию перед обновлением. Получение кода из Git само по себе не обновляет работающие контейнеры.

Для обновлений другу достаточно чтения репозитория. Настоящие IP, почтовые пароли и ключи не коммитятся. При передаче нового архива исходников сохраняйте `deployment/.env` и `deployment/data/`.

## Если что-то не работает

Если не открывается `http://94.125.99.135:3000/`, сначала выясните, **какая команда запущена на компьютере с этим IP**. `Start-QStudy.cmd` запускает локальную разработку, обычно на `127.0.0.1:3000`; это не публикация в интернете. В production порт 3000 допустим, но он должен одновременно совпадать в `deployment/.env`, контейнерном входном порту, Windows Firewall и правиле роутера.

Для **новой** конфигурации с указанным адресом либо уже совпадающей конфигурации на компьютере друга:

```powershell
.\Start-QStudy-Internet.cmd -PublicIP 94.125.99.135 -Port 3000
```

Если порт 3000 занимает ваш локальный режим, остановите его через `Stop-QStudy.cmd`, затем повторите интернет-запуск. Для новой установки можно выбрать свободный порт 8080 и использовать его в адресе и пробросе. Чужие процессы скрипт не завершает. Если существующая production-конфигурация содержит другой IP/порт, команда откажется менять их; используйте раздел 10, сохранив секреты и данные.

Для разбора ошибки выполните на **хосте друга**:

```powershell
.\Manage-QStudy-PublicAccess.cmd status
.\Manage-QStudy-Internet.cmd status
.\Test-QStudy-HomeNetwork.cmd -HttpPort 3000
```

В последней команде используйте фактический сохранённый порт. Смотрите этап ошибки запуска и `mapping_status`: `manual_required` означает, что роутер нужно настроить вручную. Если запуск пишет «QStudy работает на хосте», но телефон без Wi-Fi не открывает сайт, проверьте входящий порт у провайдера, WAN, правило роутера и сторонний firewall. Если телефон открывает, а домашний браузер нет, причина может быть в NAT loopback. Для поддержки передавайте строки ошибки и состояния без `.env`, паролей, токенов и закрытых ключей.

| Симптом | Что проверить |
| --- | --- |
| Docker установлен, но нет Server | Docker Desktop, Linux Engine, WSL, виртуализацию и перезагрузку |
| Мастер отклоняет IP | Настоящий глобальный IPv4 без CGNAT; совпадение с текущим внешним адресом и известным WAN |
| Нет доступа извне | Выбранный TCP-порт у провайдера, проброс на закреплённый LAN-IP и действующий профиль firewall |
| Автоматический проброс сообщает `manual_required` | Поддержку и разрешение UPnP/NAT-PMP в роутере, конфликт выбранного порта; при необходимости `manual` и ручной проброс |
| Продление просит повторить настройку | Изменение LAN-IP, шлюза, публичного IP или порта; согласованно обновить настройки и повторить `enable` |
| Порт занят | Освободить его владельцем процесса либо согласованно выбрать другой порт в `.env` и сети |
| Мобильный интернет работает, домашний Wi-Fi нет | NAT loopback на роутере; использовать тот же публичный адрес |
| Главная работает, вход или запись дают 403 | Точное соответствие IP, порта и `http://` полям конфигурации; отсутствие обходного Host |
| Браузер открывает HTTPS | Ввести полный `http://IP:PORT`; проверить настройки автоматического HTTPS браузера |
| База пустая | Исходники не содержат данные; проверить восстановление штатного ZIP |
| Письмо содержит localhost или старый IP | Исправить `PUBLIC_BASE_URL`, применить `start` и запросить новую ссылку |
| После перезагрузки сайт недоступен | Вход в Windows, запуск Docker, задачу QStudy и сон |
| ИИ не отвечает | Ключ, доступную модель, квоту и исходящий интернет |

Подробнее: [другой вариант с доменом и HTTPS](deployment.md), [домашний хостинг и диагностика](home-hosting.md), [пользование и администрирование](user-guide.md), [самостоятельное изменение проекта](customization.md).

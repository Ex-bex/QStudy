# Почта QStudy

Восстановление пароля отправляется через настроенный SMTP-сервер. При заполненном `SMTP_FROM` без имени отправитель автоматически отображается как **QStudy**. Адрес отправителя и пароль хранятся только в `backend/.env`, который исключён из Git.

## Gmail

1. Включите двухэтапную аутентификацию в аккаунте отправителя.
2. Создайте [пароль приложения Google](https://myaccount.google.com/apppasswords) для QStudy. Используйте его вместо обычного пароля Gmail. [Справка Google](https://support.google.com/accounts/answer/185833?hl=ru).
3. Замените соответствующие строки в `backend/.env`:

```dotenv
RECOVERY_DELIVERY=smtp
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_USERNAME=your_email@gmail.com
SMTP_PASSWORD=your_google_app_password
SMTP_FROM=QStudy <your_email@gmail.com>
```

В обоих адресах укажите выбранную почту отправителя. Пароль приложения вставьте без пробелов между группами символов. Для Gmail используются `smtp.gmail.com`, порт `587` и STARTTLS. [Настройки Google](https://support.google.com/a/answer/176600?hl=en).

## Проверка и применение

Из папки проекта выполните:

```powershell
.\backend\.venv\Scripts\python.exe .\scripts\check_mail.py
```

Проверка устанавливает соединение с SMTP, проверяет TLS-сертификат и вход с заданными учётными данными. Писем она не отправляет и паролей, адресов или ответов провайдера не выводит. Успех возвращает `ok: true`; ошибка возвращает этап и безопасный тип ошибки с ненулевым кодом завершения. Для SMTP без авторизации успешное соединение само по себе не подтверждает разрешение отправлять письма.

После изменения `.env` выполните `Stop-QStudy.cmd`, затем `Start-QStudy.cmd`. Работающий сервер загружает настройки при запуске. На странице «Забыли пароль?» запросите восстановление для существующего активного аккаунта и проверьте входящие и спам. Подтверждение входа в SMTP проверяет учётные данные; реальный запрос на сайте проверяет доставку письма провайдеру.

Ссылка действует 30 минут по умолчанию и только один раз. Новый запрос отменяет предыдущую ссылку. Пароль аккаунта меняется только после подтверждения нового пароля на странице восстановления.

## Перенос и публичный сервер

При копировании проекта на свой новый компьютер сохраните приватный `backend/.env` вместе с базой и загрузками. В GitHub передаются только код и примеры настроек. Владелец нового хоста должен проверить SMTP командой выше после установки окружения.

Локальный запуск автоматически подставляет реальный адрес и свободный порт в ссылки восстановления. Адрес `127.0.0.1` открывается только на компьютере сервера. Для устройств одной сети используйте `Start-QStudy-LAN.cmd`. Для публичного размещения нужны HTTPS, внешний адрес сайта в `PUBLIC_BASE_URL` и SMTP; публикация репозитория в GitHub сама по себе не размещает сайт в интернете.

В подготовленном Linux-развёртывании заполните соответствующие поля в закрытом `deployment/.env`, сохранив настоящий `PUBLIC_BASE_URL` с HTTPS. Конфигурация Windows не применяется к контейнерам автоматически. Из корня проекта на сервере:

```bash
sudo bash scripts/production/Manage-QStudy.sh start
sudo bash scripts/production/Manage-QStudy.sh mail-check
```

При включённом SMTP запуск тоже проверяет соединение, TLS и вход до открытия сервисов. Эти проверки писем не отправляют. Реальную доставку и публичную ссылку подтвердите запросом восстановления своего аккаунта на HTTPS-сайте. Полная последовательность сервера и переноса данных — в [инструкции развёртывания](deployment.md).

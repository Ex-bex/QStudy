# Самостоятельное изменение QStudy

Есть три уровня изменений: данные через админку, настройки сервера и исходный код. Учебные данные, аккаунты, изображения и контакты удобнее изменять в интерфейсе: такие изменения сохраняются в базе и переживают обновление кода.

Использование разделов описано в [руководстве пользователя](user-guide.md); новый Windows-запуск и перенос — в [инструкции запуска](startup.md), белый IP — в [инструкции для друга](friend-hosting.md).

## Что можно изменить без программирования

| Задача | Где менять |
| --- | --- |
| Создать группу, переименовать её, уточнить программу и семестр | «Группы и расписание», административный аккаунт |
| Добавить дисциплину, преподавателя, пару или кабинет | Страница группы |
| Изменить неделю, материалы, задания, модуль или сроки | Страница дисциплины |
| Прочитать новый силабус и заполнить план | «Силабусы», выбор дисциплины и загрузка PDF/DOCX |
| Поменять имя, роль, группу или доступ пользователя | «Администратор» → аккаунты |
| Назначить пользователю новый пароль | Отдельная команда смены пароля в аккаунтах |
| Заменить основной PNG-логотип | «Администратор» → «Логотип проекта» |
| Изменить подразделения, руководителей, контакты и изображения | «Администратор» → «Команда QForce» |
| Править своё имя или пароль | «Мой профиль» |
| Править название и текст своей заметки | «Мои заметки» |
| Переименовать свой файл, изменить предмет/тему | Карточка «Моих материалов» |
| Исправить свои конспекты, задачи, карточки и диалоги | Соответствующий учебный инструмент |
| Изменить SMTP, ключ ИИ и общие параметры | «Администратор» → «Система» |
| Скачать проект с данными, загрузить и применить ZIP | «Администратор» → «Система» |
| Перезапустить или остановить сайт | «Администратор» → «Система», при запуске новым стартером |

Новые логотипы и контакты на `/developers` видны посетителям без входа. Не загружайте туда приватные документы и не публикуйте личные контакты, не предназначенные для сайта.

## Настройки сервера

### Windows

Почту, ИИ и общие параметры удобнее менять в админке → «Система». Пустые поля секретов сохраняют прежние значения. Рабочий файл обычной установки — `backend/.env`; если выбрано прежнее контейнерное хранилище, это `deployment/.env`. Не вставляйте его содержимое в сообщения, GitHub, скриншоты или публичные отчёты. Шаблон `backend/.env.example` показывает параметры; не копируйте его поверх действующего файла.

После изменения настроек нажмите «Перезапустить» в разделе «Система». Настройки загружаются при запуске. Все три стартера используют одну базу; режим интернета определяет внешний адрес и использует 8080, локальный и LAN выбирают свободный порт.

### Публичный сервер

Рабочая конфигурация контейнерного запуска находится в `deployment/.env`. Она исключена из Git и не включается в образ. Не заменяйте этим файлом Windows-настройки, если продолжаете пользоваться локальной установкой. Правила применения конфигурации и команда запуска приведены в [deployment.md](deployment.md).

### Основные параметры

| Параметр | Что изменить и чего ожидать |
| --- | --- |
| `GEMINI_API_KEY` | Ключ ИИ из своего аккаунта провайдера. Без него генерация недоступна, а силабус остаётся сохранённым для повторного импорта |
| `GEMINI_MODEL` | Доступная вашему ключу модель; модель и квота проверяются реальным запросом |
| `WEB_RESEARCH_ENABLED` | Включение поиска публичной теории для ИИ. Для поиска нужны поддержка модели и доступная квота |
| `GEMINI_WEB_MODEL` | Необязательная отдельная модель поиска; пустое значение использует основную |
| `WEB_RESEARCH_TIMEOUT_SECONDS`, `WEB_RESEARCH_MAX_SOURCES` | Предел времени одного поиска и число найденных источников |
| `REGISTRATION_ENABLED` | `false` закрывает самостоятельную регистрацию: аккаунты создаёт администратор |
| `PUBLIC_BASE_URL` | Доверенный адрес сайта без пути: для интернета `https://ваш-домен`. Нужен в ссылках восстановления |
| `RECOVERY_DELIVERY` | `smtp` для самостоятельного восстановления по почте, `local` только для локального сайта, `disabled` для отключения |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY` | Почтовое соединение: обычно STARTTLS/587 или TLS/465; настройка от провайдера |
| `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` | Учётные данные и отправитель, например `QStudy <mail@example.org>`; только в закрытой конфигурации |
| `PASSWORD_RESET_MINUTES` | Срок ссылки восстановления: по умолчанию 30 минут |
| `BACKUPS_ENABLED` | `true` включает автоматические копии |
| `BACKUP_INTERVAL_HOURS`, `BACKUP_RETENTION_COUNT` | По умолчанию раз в 24 часа, последние 14 готовых копий |
| `BACKUP_DIR` | Папка копий. В локальной установке путь по умолчанию `.backups/automatic/`; в контейнере путь связан с постоянным томом |
| `JOB_WORKERS`, `JOB_LEASE_SECONDS`, `JOB_MAX_ATTEMPTS` | Параметры очереди ИИ; по умолчанию 2 исполнителя, блокировка 90 секунд и 3 попытки |
| `MAX_UPLOAD_BYTES` | Backend-предел обычного файла, по умолчанию 25 МиБ; отдельные пределы BFF и силабусов тоже должны соблюдаться |
| `RATE_LIMIT_ENABLED` | Ограничение частоты запросов; оставляйте включённым при сетевом доступе |
| `SECRET_KEY` | Случайный секрет, минимум 32 символа. Замена отзовёт действующие токены. Не используйте пароль администратора вместо секрета |
| `BFF_PROXY_SECRET` | Отдельный случайный секрет доверенного шлюза; в публичном запуске одинаковый у frontend и backend. Не передаётся браузеру |
| `DATABASE_URL`, `UPLOAD_DIR` | Расположение базы и загрузок. При изменении перенесите реальные данные, иначе можно открыть новую пустую базу |

Имя `studyhub.db` сохраняется для совместимости. Название интерфейса QStudy не требует переименования базы. Файлы SQLite, `-wal` и `-shm` нельзя несогласованно копировать из работающего сервера: используйте штатную резервную копию или сначала остановите приложение.

Проверка почты на Windows, из корня проекта:

```powershell
.\backend\.venv\Scripts\python.exe .\scripts\check_mail.py
```

Она проверяет соединение, TLS и вход, но не отправляет письмо. Для полной проверки запросите восстановление **своего существующего аккаунта** на сайте. [Настройка Gmail и применение SMTP](mail.md).

### Изменение текста, цвета и изображения

Для текста найдите точную текущую фразу в `frontend/`, например в редакторе через поиск по папке, и измените соответствующий JSX. Общие цвета и размеры правятся в подключённых CSS; стили отдельного раздела могут находиться рядом с компонентом. После изменения проверьте главный экран, формы и мобильную ширину.

Основной логотип и изображения департаментов сначала меняйте через админку. Если вы сознательно обновляете **стандартные** изображения исходников, используйте `frontend/public/brand/` и проверьте ссылки в `frontend/lib/branding.ts`. У загруженного через админку логотипа приоритет выше стандартного; сначала верните стандартный в админке, чтобы увидеть новую исходную картинку. Не кладите секретные или личные файлы в `public/`: всё содержимое этой папки доступно посетителям.

### Добавление страницы и функции

1. Прочитайте `frontend/AGENTS.md` и локальную документацию установленной версии Next.js в `frontend/node_modules/next/dist/docs/`. API фреймворка зависит от версии; старый пример из интернета может не подходить.
2. Создайте папку маршрута, например `frontend/app/dashboard/example/page.tsx`. Для новой страницы кабинета добавьте ссылку в `dashboard/layout.tsx`; если она только административная, показывайте её в административной части меню.
3. Данные получайте через существующий API-клиент `frontend/lib/api.ts` и адреса `/api` своего сайта. Не помещайте ключи SMTP/ИИ и backend-токены в клиентский код или переменные `NEXT_PUBLIC_*`.
4. Если нужны новые операции, создайте или расширьте router в `backend/app/routers/` и подключите его в `main.py`. Для глобальных изменений требуйте роль администратора; для личных — проверяйте владельца записи. Одного скрытия кнопки мало.
5. Проверяйте входные поля и отношения группы/дисциплины/предмета на сервере. Общие административные изменения записывайте в журнал в той же транзакции. Не записывайте пароли, токены и тексты личных документов в журнал.
6. Если меняются таблицы, добавьте миграцию, сохраняющую существующие записи, а не удаляйте рабочую базу. Новые задания ИИ подключайте к долговечной очереди, а не к памяти вкладки.
7. Проверьте сценарий студента и администратора, отказ чужому аккаунту, пустые данные, ошибки сети и телефон. Запустите проверки ниже и создайте копию перед применением обновления на сервере.

Не меняйте маркеры однократного импорта в базе ради повторной загрузки справочника. Перезапуск уже не повторяет импорт и не восстанавливает удалённые записи; новая редакция силабуса загружается через интерфейс.

## Работа с изменениями на Windows

Разработку выполняйте на отдельной копии с тестовыми данными. Если используете рабочую базу, сначала скачайте копию. `Start-QStudy.cmd` запускает production-сборку: после изменения кода остановите сайт в админке и снова запустите стартер, чтобы он пересобрал интерфейс. Для разработки Next.js отдельно доступен `npm run dev` в frontend.

Из корня проекта создайте ветку с понятным именем:

```powershell
git status --short
git switch -c codex/my-change
```

Проверки backend:

```powershell
Set-Location .\backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Set-Location ..
```

Проверки frontend:

```powershell
Set-Location .\frontend
node --test lib/learning-selection.test.mjs lib/syllabus-draft.test.mjs lib/branding.test.mjs lib/branding-store.test.mjs lib/proxy-security.test.mjs
npm run lint
npm run build
Set-Location ..
```

Проверка состава Git, из корня:

```powershell
.\backend\.venv\Scripts\python.exe .\scripts\check_repository.py
git diff --check
git diff --stat
```

Установка новых зависимостей меняет lockfile. Для frontend после обдуманного `npm install имя-пакета` сохраните `package.json` **и** `package-lock.json`; при воспроизведении используйте `npm ci`. Для backend обновите `requirements.txt` и согласованный `requirements.lock.txt`, проверьте совместимость и аудит. Не запускайте случайное массовое обновление на рабочем хосте без копии и проверки.

Перед сохранением изменений просмотрите `git diff`, добавьте конкретные исходники и документацию, затем создайте commit. Не используйте `git add -f` для `.env`, базы, загрузок или приватных ZIP. Для принятия изменений используйте Pull Request; после проверок примените их на сервере. Приватность репозитория не заменяет защиту секретов.

```powershell
git add docs/user-guide.md docs/customization.md
git diff --cached --stat
git commit -m "Update QStudy documentation"
git push -u origin codex/my-change
```

Приведённые пути — пример изменения документации. Подставьте свои реальные изменённые файлы. Репозиторий хранит код; обновление `git push` само по себе не обновляет запущенный сайт и не переносит пользовательские данные.

## Обновление локальной установки

1. Создайте и скачайте резервную копию, отдельно сохраните закрытый `.env`.
2. Остановите сайт в админке → «Система» и дождитесь завершения.
3. Убедитесь через `git status --short`, что собственные правки сохранены. Получите проверенную версию основной ветки; `git pull --ff-only` применяет её только без конфликтующего расхождения истории. При конфликте сначала сохраните правки и разберите различия, не используйте принудительный сброс ради обновления.
4. Выполните `Start-QStudy.cmd`: он проверит зависимости, при необходимости обновит среду и применит миграции. Первый запуск после изменения зависимостей может требовать интернет.
5. Проверьте вход, группу, личные данные, файлы, ИИ и состояние копирования. Если новая версия не запускается, сначала изучите `.local/logs/`; сохраните ошибку без секретов.

Не копируйте поверх рабочей базы пустую базу из другой установки и не заменяйте действующий `.env` примером. Код и данные обновляются отдельно.

## Диагностика установки и перенос

| Ситуация | Команда или проверка |
| --- | --- |
| Нужно проверить и подготовить среду | `Install-QStudy.cmd` |
| Повреждено окружение Python/Node или нужно повторить подготовку OCR | Остановите сайт, затем `Install-QStudy.cmd -ForceRepair` |
| Нет интернета, но среда уже установлена | `Start-QStudy.cmd -Offline` |
| Нужно открыть на телефоне в одной сети | `Start-QStudy-LAN.cmd`, затем показанный LAN-адрес |
| Порт 3000 занят | Обычный запуск сам найдёт свободный порт; используйте фактический адрес из окна запуска |
| Не работает восстановление | `scripts/check_mail.py`, настройки SMTP, публичный адрес и перезапуск |
| Нужен первый администратор | Новый стартер предложит создать его только при отсутствии активного администратора; существующие аккаунты не сбрасываются |
| Нужна проверка или загрузка ZIP-копии | «Администратор» → «Система» → загрузка, предпросмотр и явное применение |

Для переноса скачайте полный приватный ZIP в админке → «Система». При переносе через Git отдельно передайте базу, `uploads/`, рабочий `.env` и при необходимости `local-documents/`: они исключены из Git. Для копирования всей папки сначала остановите приложение. [Подробная последовательность](startup.md).

# QStudy

Учебная платформа на Next.js и FastAPI: группы, расписание с кабинетами, учебный план по неделям, модульные работы и ответы студентов, силабусы с анализом ИИ, личные заметки, файлы, карточки, тренажёр, тесты, экзаменатор и чат.

Есть две роли. Администратор управляет общей учебной информацией и аккаунтами. Студент читает общую информацию и работает со своими материалами, прогрессом и ответами. Проверки прав выполняются сервером; скрытие кнопок в интерфейсе не заменяет авторизацию.

## Структура проекта

| Папка | Содержимое |
| --- | --- |
| `frontend/` | Интерфейс Next.js, компоненты и стандартные изображения в `public/brand/` |
| `backend/` | API FastAPI, тесты, шаблон настроек и локальные данные приложения |
| `scripts/` | Установка среды, запуск, перенос, резервное копирование и восстановление |
| `assets/brand/source/` | Оригинальные PNG, JPEG и PSD логотипов QForce |
| `docs/` | [Учебная структура](docs/academic.md), [хранение и доступ](docs/security.md), краткая инструкция запуска |
| `local-documents/` | Личные исходные PDF, DOCX и HTML; исключены из Git |
| `.local/`, `.backups/` | Служебное состояние и резервные копии; исключены из Git |

В корне оставлены README, лицензия и команды запуска для двойного щелчка. Исходники публикуются в закрытый репозиторий `Ex-bex/QStudy`; рабочие настройки, аккаунты и пользовательские файлы в Git не передаются. Проверки CI выполняются на Windows с тестовыми данными.

## Перенос и автоматический запуск на Windows

Поддерживается 64-битная Windows 10/11. Для первого запуска и установки недостающих зависимостей нужен интернет. Ключ ИИ устанавливается отдельно: установщик не может получить его вместо владельца аккаунта.

1. На старом компьютере выполните `Stop-QStudy.cmd` и скопируйте папку проекта на новый компьютер.
2. Обязательно перенесите `backend/studyhub.db`, `backend/uploads/`, `backend/.env` и `local-documents/`, чтобы сохранить аккаунты, материалы, исходные документы и настройки ИИ. Загруженные логотипы включены в базу. В обычной копии всей папки они уже включены; при переносе только Git-репозитория эти исключённые из Git файлы необходимо скопировать отдельно.
3. На новом компьютере дважды нажмите `Start-QStudy.cmd`. Он проверит среду, установит недостающие компоненты, запустит QStudy и откроет действительный адрес в браузере.

Для уменьшения размера копии можно пропустить `frontend/node_modules/`, `frontend/.next/`, `backend/.venv/`, `backend/venv/`, `.local/` и `.backups/`. Установщик восстановит зависимости. Если эти папки скопированы, служебное состояние и окружения проверяются заново; старые процессы и пути другого компьютера не используются вслепую. Резервные копии перенесите отдельно, если они нужны.

`Install-QStudy.cmd` устанавливает среду отдельно от запуска. Проверяются подходящие Python 3.13, Node.js 22/24 и npm; при необходимости загружаются пакеты Python Software Foundation и официальный архив Node.js с проверкой контрольных сумм. Затем создаётся окружение `backend/.venv/`, устанавливаются `backend/requirements.txt` с зафиксированными версиями всех 38 пакетов из `backend/requirements.lock.txt` и зависимости frontend по `package-lock.json`. Установка Python, Node.js и библиотек не требует прав администратора Windows и изменения системного PATH. Недостающий `backend/.env` создаётся с новым случайным секретом. Существующий файл настроек сохраняется.

`Install-QStudy.cmd -CheckOnly` проверяет готовность без установки. Для восстановления окружения остановите сайт и выполните `Install-QStudy.cmd -ForceRepair`. `Start-QStudy.cmd -Offline` запускает уже подготовленную среду без скачивания; первый запуск на новом компьютере требует интернета. Заменённые окружения сохраняются в `.local/retired/` для восстановления и могут занимать место.

При подготовке среды также проверяется русский распознаватель Windows для PDF-сканов. Если его нет, установщик добавляет фиксированные компоненты `Language.Basic~~~ru-RU~0.0.1.0` и `Language.OCR~~~ru-RU~0.0.1.0` через Windows Update. Для системных компонентов Windows может запросить стандартное подтверждение UAC. Язык интерфейса Windows не меняется; автоматической перезагрузки нет. При отказе, отсутствии сети или ошибке Windows Update само приложение продолжает запускаться, а доступность OCR сохраняется отдельно в `.local/ocr-runtime.json`. После неудачной попытки действует пауза 24 часа; `-ForceRepair` позволяет повторить подготовку. При переносе на другой компьютер старый статус не считается подтверждением готовности. `-CheckOnly` не создаёт файлы, не устанавливает компоненты и не вызывает UAC. [Компоненты языков Windows](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/features-on-demand-language-fod?view=windows-11).

По умолчанию сайт доступен на этом компьютере. Предпочтительные порты — 3000 для сайта и 8000 для API; занятый порт автоматически заменяется свободным. Чужие процессы не останавливаются. Фактический адрес выводится в окне запуска и сохраняется в `.local/processes.json`; браузер открывается после проверки готовности серверов. Повторный запуск использует уже работающий экземпляр.

Для других устройств в одной локальной сети используйте `Start-QStudy-LAN.cmd`. Он показывает адрес компьютера и выбранный порт; backend остаётся доступен только через loopback. На другом устройстве откройте показанный LAN-адрес. Если Windows запросит разрешение для сети, используйте доверенную частную сеть. Скрипт не меняет правила брандмауэра автоматически. При нескольких сетевых интерфейсах проверьте, что устройства находятся в той же сети.

Сейчас этот запуск использует сервер разработки Next.js и HTTP. Он предназначен для локальной работы и проверки в доверенной сети. Публичный сервер требует HTTPS и производственного развёртывания из раздела ниже. Автоподбор порта и локального IP не создаёт публичный адрес в интернете.

Серверы работают в фоне и не зависят от окна терминала. Для остановки используйте `Stop-QStudy.cmd`. После перезагрузки Windows снова запустите `Start-QStudy.cmd`: службы и автозапуск в систему не устанавливаются. Журналы сохраняются в `.local/logs/`; если запуск не удался, окно покажет причину и расположение журналов.

Изменения интерфейса подхватываются автоматически. После изменения Python-кода выполните `Stop-QStudy.cmd`, затем `Start-QStudy.cmd`. Не публикуйте скопированную папку или архив проекта с базой, загруженными документами и `.env`.

### Установка зависимостей и ручной запуск

Нужны Python 3.13, Node.js не ниже 20.9 и npm. Команды ниже выполняются из корня проекта, если не указано другое. Не копируйте `.env.example` поверх существующего `.env`: там находятся настройки действующей базы и ключ ИИ.

В первом терминале:

```powershell
Set-Location .\backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -c requirements.lock.txt
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
    $qstudySecret = .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
    (Get-Content -LiteralPath .env -Raw).Replace('replace_with_a_random_secret_at_least_32_characters', $qstudySecret) | Set-Content -LiteralPath .env -Encoding utf8
}
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Для приведённой команды используйте папку `backend`. Настройки, относительные пути базы и загрузок привязаны к расположению backend, а не к рабочей папке процесса. Для разработки можно добавить `--reload`. При запуске применяются миграции, сохраняющие существующие записи.

Во втором терминале из корня проекта:

```powershell
Set-Location .\frontend
npm ci
$env:BACKEND_URL = 'http://127.0.0.1:8000'
npm run dev -- --port 3000
```

Откройте [QStudy](http://127.0.0.1:3000). Проверка backend: [health](http://127.0.0.1:8000/api/health). Браузер обращается к `/api` на том же сайте; Next.js передаёт запросы в FastAPI. `BACKEND_URL` — серверная настройка, префикс `NEXT_PUBLIC_` ей не нужен.

## Первый администратор

Регистрация всегда создаёт студента. Первый зарегистрированный пользователь автоматически администратором не становится.

В третьем терминале, из папки `backend`:

```powershell
.\.venv\Scripts\python.exe -m app.bootstrap_admin your-email@example.com --name 'Администратор'
```

Команда дважды запросит новый пароль скрытым вводом. Для существующего email она выдаст административную роль, обновит пароль и отзовёт предыдущие сессии; для нового — создаст аккаунт. Пароль: 10–128 символов, минимум буква и цифра. Затем войдите на сайт и откройте раздел управления аккаунтами.

Администратор может создавать аккаунты, менять имя, email, роль и группу, блокировать вход, сбрасывать пароль и удалять аккаунты. Изменения прав, блокировка, смена пароля и выход отзывают соответствующие сессии. Нельзя удалить себя, снять с себя права или оставить систему без действующего администратора. Удаление аккаунта удаляет его личные данные; общий учебный план сохраняется.

## Автоматические копии и журнал управления

Резервная копия базы SQLite и загруженных файлов создаётся перед обновлением структуры приложения и затем раз в 24 часа, пока сервер работает. Сохраняются последние 14 проверенных ZIP-архивов в `.backups/automatic/`. В копии входят согласованный снимок базы, приватные загрузки и манифест с SHA-256; перед сохранением проверяются архив, файлы и целостность базы. Незавершённый архив не считается готовой копией. При выключенном сервере расписание не выполняется; после запуска проверяется необходимость новой копии.

В управлении администратора доступны состояние копирования, список архивов, создание копии вручную и скачивание. Архивы содержат личные учебные данные: храните их защищённо. `.env` и ссылки восстановления паролей в архив не включаются, поэтому настройки и ключи необходимо отдельно сохранить защищённым способом. Копии на одном диске не защищают от поломки или потери компьютера; переносите готовые архивы на отдельный носитель.

Проверка и восстановление из корня проекта:

```powershell
.\Restore-QStudy.cmd -Archive 'C:\Backups\qstudy-backup.zip' -VerifyOnly
.\Stop-QStudy.cmd
.\Restore-QStudy.cmd -Archive 'C:\Backups\qstudy-backup.zip'
.\Start-QStudy.cmd
```

Восстановление разрешено только при остановленном QStudy. Перед заменой данных создаётся копия текущего состояния. Настройки `.env` сохраняются; старые сессии и ссылки восстановления отзываются, незавершённые задания ИИ возвращаются в очередь. Не используйте произвольный ZIP: принимаются проверенные архивы этого приложения.

Журнал администратора фиксирует время, исполнителя, действие, объект и названия изменённых полей для аккаунтов, групп, расписания, дисциплин, недель, работ и силабусов. Запись сохраняется в той же транзакции, что и изменение. Пароли, токены, содержимое документов и личных ответов в журнал не записываются. Через приложение записи журнала нельзя редактировать или удалять; доступ к журналу имеет только администратор.

## Восстановление пароля

На странице входа есть «Забыли пароль?». Ссылка действует 30 минут, используется один раз, и при смене пароля закрываются прежние сессии. В базе хранится хеш ссылки; её полный адрес не возвращается через API и не попадает в серверные URL-журналы. Поведение основано на [рекомендациях OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).

Для текущего localhost без SMTP включается локальный режим: сообщение сохраняется в `.local/recovery/`, которая не доступна через сайт. На компьютере сервера владелец может запустить `Open-QStudy-Recovery.cmd`, указать email и открыть ссылку без вывода токена в консоль. Сначала необходимо запросить восстановление на сайте. В локальной сети студент обращается к владельцу сервера; для самостоятельного восстановления через почту подключите SMTP.

Для писем задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, при необходимости `SMTP_USERNAME` и `SMTP_PASSWORD` в `backend/.env`. `SMTP_SECURITY=starttls` используется обычно с портом 587, `ssl` — с 465. Обе схемы проверяют TLS-сертификат. `RECOVERY_DELIVERY=auto` выбирает SMTP при наличии конфигурации; `smtp` требует почту, `local` разрешён только с локальным адресом сайта, `disabled` отключает функцию. Для публичного сайта задайте `RECOVERY_DELIVERY=smtp` и HTTPS-адрес `PUBLIC_BASE_URL`. Локальный launcher автоматически передаёт действительный IP и порт сайта для ссылки восстановления.

Если в `SMTP_FROM` указан только email, письмо отображает имя отправителя **QStudy**. [Настройка Gmail, проверка SMTP и перенос почты на другой хост](docs/mail.md).

## Задания ИИ после перезапуска

Лекции, тесты, задания тренажёра, карточки, обработка файлов, создание экзамена и импорт силабусов используют постоянную очередь в базе. Страница «Задания ИИ» показывает свои последние 100 заданий, состояние и переход к результату. Закрытие вкладки не удаляет задание. Статусы и уведомления сохраняются; готовый ответ ИИ фиксируется перед применением результата, а создание записей и завершение задания выполняются одной транзакцией.

После аварийной остановки сервер автоматически подхватывает прерванные задания после истечения блокировки worker — по умолчанию до 90 секунд. Временные ошибки повторяются до трёх попыток; постоянная ошибка остаётся видна для повторного запуска из соответствующего раздела. Если авария произошла до сохранения ответа провайдера, вызов ИИ может быть повторён. Интерактивные сообщения чата и проверка конкретного ответа остаются обычными запросами; уже сохранённые сообщения и ответы находятся в базе.

## Учебные инструменты по программе и актуальные источники

Тесты, тренажёр, карточки, экзаменатор, лекции и чат используют опубликованные недели и модульные работы дисциплины. Откройте группу → дисциплину и нажмите действие у модуля, недели или работы: выбранный источник подставится автоматически. В самих инструментах можно переключаться между «По силабусу» и «Мои предметы», выбрать модуль, несколько недель или конкретные работы. При выборе работ используются только их задания; остальные темы недели не добавляются. Пустая или недоступная программа не превращается в выдуманный учебный план.

Студент использует программу своей группы; администратор может выбрать любую доступную группу. Созданные тесты, карточки, упражнения, экзамены и лекции остаются личными. Изменение программы или доступа к группе во время выполнения останавливает публикацию устаревшего результата. Повторный одинаковый запрос на карточки или упражнения во время выполнения не создаёт второе задание.

Флажок «Проверить актуальность в интернете» включён по умолчанию в интерфейсе. Отдельный запрос Gemini с Google Search получает только названия публичных учебных тем. Текст личных заметок, ответы, документы, данные группы и история диалога не передаются инструменту поиска. Обычная генерация по выбранным материалам продолжает использовать настроенного провайдера ИИ. Интернет уточняет теорию и примеры, сохраняя темы и требования силабуса; расписание и задания преподавателя автоматически из интернета не меняются.

У результата сохраняются выбранная программа, ссылки из подтверждённых поисковых метаданных и время проверки. Это время относится к поисковой проверке, а не подтверждает каждый факт ответа. Без подтверждённых ссылок, при недоступности сети, модели или квоты показывается «Интернет не проверен»; генерация продолжается по учебным данным. Такой результат не получает отметку успешной интернет-проверки. Завершённые этапы поиска и генерации сохраняются в постоянной очереди и используются после перезапуска без повторения уже сохранённого этапа. Чат сохраняет источники в истории сообщений, но отправка сообщения остаётся обычным запросом.

Для поиска используется существующий `GEMINI_API_KEY`. Дополнительный ключ не требуется; доступность Google Search и его квота зависят от аккаунта провайдера. `WEB_RESEARCH_ENABLED=false` отключает поиск на сервере. Необязательный `GEMINI_WEB_MODEL` позволяет выбрать другую поддерживающую поиск модель; пустое значение использует `GEMINI_MODEL`. [Google Search grounding](https://ai.google.dev/gemini-api/docs/google-search).

## Силабусы и исходные документы

Группа «ИП-26-3кс» создаётся при первом запуске. Проверенный предоставленный DOCX импортируется один раз: курс, 15 недель и 8 работ. Импорт сверяет SHA-256 исходника и не перезаписывает последующие правки администратора. Если оригинального DOCX нет или его содержимое изменилось, автоматический импорт пропускается. Отдельный исходный PDF состоит из девяти отсканированных страниц без текстового слоя; для него используется автоматическое локальное OCR.

DOCX задаёт программу дисциплины, а расписание взято из отдельно предоставленного `local-documents/spravochnik-9.html`. Его снимок от 29 сентября 2026 года содержит 61 группу, программы обучения, предметы, преподавателей и кабинеты. Сверены контрольные суммы двух вложенных Excel-книг, ячейки исходников и данные HTML. Для «ИП-26-3кс» перенесены 8 дисциплин и 15 времён начала занятий в 9 записях расписания. Программа «Мамандыққа кіріспе» с 15 неделями и 8 работами сохранена.

В списке групп доступны поиск и фильтры; в группе — расписание по дням и неделям, поиск по предметам, преподавателям и кабинетам, переход к программе дисциплины и сведения об источнике. Общую информацию редактирует администратор. Учебные данные своей группы доступны ИИ при ответах на соответствующие вопросы.

Время вида `08:30 / 09:35` обозначает два начала занятий. Конец пары, периодичность, подгруппы и даты семестра в справочнике не определены; приложение не достраивает их самостоятельно. Кабинет `806Г-708Г` сохранён как в исходнике. У 37 групп есть конфликт между названием листа «2-курс» и заголовком «3 курс, 5 семестр», поэтому курс обучения оставлен неподтверждённым. У 24 групп первого курса указаны 1 курс и 1 семестр. Пустой день означает отсутствие записей в снимке. Актуальность расписания после указанной даты необходимо сверять у куратора.

Расписание импортируется один раз с проверкой SHA-256 HTML и вложенных книг. Повторный запуск не возвращает удалённые записи и не перезаписывает правки администратора. Уже удалённая или переименованная группа не создаётся заново при перезапуске. Новые программы по неделям добавляются из соответствующих силабусов: сам справочник их не содержит.

На странице силабусов администратор выбирает группу и дисциплину и загружает PDF или DOCX. Извлечение текста, постановка в очередь и анализ ИИ запускаются автоматически. В пустой дисциплине проверенный по структуре результат автоматически создаёт недели и работы, заполняет описание, а также пустое имя преподавателя и кредиты, если они явно указаны в документе. Уже заполненные реквизиты сохраняются. Общие часы, семестр и исходная группа отображаются в сведениях силабуса; назначение дисциплины выбранной группе не меняется. Результат виден в группе, программе дисциплины и разделе работ. Повторная загрузка того же документа не создаёт дубликаты. Неизвестные даты, кабинеты и периодичность расписания из силабуса не выдумываются.

Если учебный план уже существует, документ редактировали во время анализа или в нём нет достаточной программы, результат сохраняется для проверки. Существующие недели, работы, прогресс и ответы студентов не заменяются автоматически. Администратор может проверить черновик и применить допустимые изменения. Без настроенного ИИ документ сохраняется со статусом необходимости настройки; после добавления ключа есть повторный импорт. Обычное чтение и ручное редактирование не требуют обращения к ИИ. Даже автоматически опубликованный результат следует проверить на соответствие исходнику и выбранной дисциплине.

Строки с обнаруженными данными доступа исключаются из извлечённого текста и контекста ИИ. Оригинал такого документа доступен только администратору; файл-источник в проекте не изменяется. Автоматическое распознавание чувствительных строк не заменяет проверку документа перед публикацией.

PDF со сканами автоматически проходит локальное распознавание в постоянной очереди: на Windows 10/11 используется встроенный Windows.Media.Ocr с русским распознавателем. Оригинальный PDF не меняется и для OCR не отправляется во внешний сервис. Страницы с готовым текстом сохраняют его; распознаются только страницы с изображениями или графикой без достаточного текста. После OCR очищенный текст сохраняется, затем настроенный ИИ составляет программу. Без ключа ИИ распознанный текст тоже доступен; анализ можно запустить позже. Для ранее загруженного скана нажмите «Распознать и импортировать».

OCR ограничен 50 страницами за один импорт и 200 тысячами символов; большие сканы разделите. [Документация Windows.Media.Ocr](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine). Таблицы и мелкий текст после OCR необходимо сверить с оригиналом; пустые или неразборчивые страницы не превращаются в выдуманный учебный план. Если после OCR в черновике пропущены номера недель между первой и последней, ИИ автоматически повторно проверяет исходный текст. Подтверждённые недостающие строки добавляются с сохранением первоначальных тем и работ. Завершённая повторная проверка сохраняется в очереди и не повторяется после перезапуска; временная ошибка провайдера использует ограниченные попытки той же задачи. Если источник не позволяет заполнить пропуски, первый корректный черновик сохраняется для проверки и автоматическая публикация останавливается. Отсутствующие темы не выдумываются.

Предоставленный оригинальный DOCX содержит данные доступа к встречам, поэтому его точный путь добавлен в `.gitignore`; файл сохранён локально. Не публикуйте оригинал вместе с исходниками приложения. Для нового развёртывания передайте его отдельно защищённым способом, если нужен первоначальный импорт.

## Конфигурация backend

Настройки читаются из `backend/.env` и переменных окружения. Файл `.env` не должен попадать в Git или публичную раздачу файлов.

| Переменная | Назначение |
| --- | --- |
| `SECRET_KEY` | Случайный секрет минимум 32 символа. Смена аннулирует все токены. |
| `DATABASE_URL` | По умолчанию `sqlite:///./studyhub.db`. |
| `UPLOAD_DIR` | По умолчанию `./uploads`; хранение приватных файлов. |
| `GEMINI_API_KEY` | Ключ провайдера для чата, генерации, анализа и расшифровки. |
| `GEMINI_MODEL` | Модель, доступная вашему ключу. Значение задаётся в конфигурации. |
| `WEB_RESEARCH_ENABLED`, `GEMINI_WEB_MODEL` | Поиск актуальной теории включён; отдельная модель необязательна. |
| `WEB_RESEARCH_TIMEOUT_SECONDS`, `WEB_RESEARCH_MAX_SOURCES` | Один поисковый запрос: до 35 секунд и до 8 ссылок по умолчанию. |
| `CORS_ORIGINS` | Список разрешённых origin через запятую для прямого доступа к API. |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Срок токена, по умолчанию 720 минут. Cookie браузера действует до 8 часов. |
| `MAX_UPLOAD_BYTES` | Обычные файлы, по умолчанию 25 МиБ. Силабусы ограничены 20 МиБ. |
| `REGISTRATION_ENABLED` | `false` закрывает самостоятельную регистрацию. |
| `RATE_LIMIT_ENABLED` | Ограничения запросов; оставьте `true` при доступе других пользователей. |

| `JOB_WORKERS`, `JOB_LEASE_SECONDS`, `JOB_MAX_ATTEMPTS` | Два worker, блокировка 90 секунд и три попытки задания. |

Имя `studyhub.db` намеренно сохранено при переименовании приложения в QStudy: существующие аккаунты, заметки и другие записи продолжают использовать прежнюю базу. Не создавайте пустую `qstudy.db` и не удаляйте старую базу ради переименования.

## Проверка

Из `backend`:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют временные базы и файлы, не вызывают внешний ИИ и проверяют роли, принадлежность личных данных, отзыв сессий, загрузки, миграции, публикацию силабуса, расписание и сдачу работ.

Проверки переносимого установщика из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/tests/Test-QStudyInstaller.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/tests/Test-QStudyOcr.ps1
```

OCR-проверки используют временную папку и имитацию установки, не добавляют компоненты Windows и не вызывают UAC. Отдельно проверяется фактическая доступность уже установленного русского распознавателя.

В `requirements.txt` зафиксированы проверенные версии прямых зависимостей, в `requirements.lock.txt` — весь проверенный набор из 38 пакетов. JWT обрабатывается PyJWT с разрешённым алгоритмом HS256; прежние зависимости `python-jose` и `ecdsa` исключены. На 10 октября 2026 года `pip-audit` не обнаружил известных уязвимостей в этом lockfile. Аудит следует повторять при обновлении версий. Сканер запускается из отдельного окружения `uv`, без установки его зависимостей в рабочее Python-окружение.

Повторная проверка зависимостей из `backend`, если установлен `uv`:

```powershell
uv tool run --from pip-audit pip-audit --requirement requirements.lock.txt
```

Из `frontend`:

```powershell
node --test lib/syllabus-draft.test.mjs
node --test lib/learning-selection.test.mjs
npm run lint
npm run build
```

Необязательная проверка уже запущенных серверов, из `backend`. Адрес localhost и фактический порт читаются из состояния запуска:

```powershell
.\.venv\Scripts\python.exe tests/smoke_bff.py
```

Этот скрипт создаёт отдельные временные QA-аккаунты и предмет, проверяет cookie, CSRF и авторизацию и удаляет свои данные в `finally`. Используйте его на локальной проверочной среде; при принудительном завершении процесса проверьте очистку QA-данных. Скрипт учитывает особенности Secure-cookie у HTTP-клиента при локальной проверке production-сборки; работу браузера дополнительно проверяйте через HTTPS или сервер разработки.

## Резервная копия и обновление

Для согласованной копии остановите backend перед копированием базы и загрузок. Сохраните `backend/studyhub.db`, `backend/uploads/` и `.env` в защищённом хранилище. Например, из корня проекта:

```powershell
$qstudyBackup = Join-Path (Get-Location) ('backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $qstudyBackup | Out-Null
Copy-Item -LiteralPath .\backend\studyhub.db -Destination $qstudyBackup
Copy-Item -LiteralPath .\backend\uploads -Destination $qstudyBackup -Recurse
Copy-Item -LiteralPath .\backend\.env -Destination (Join-Path $qstudyBackup 'backend.env')
```

Не размещайте резервные копии в публичной папке сайта и не добавляйте их в Git. Новые загрузки хранят пути относительно папки uploads. При запуске проверяются старые пути, и подтверждённые записи переводятся в переносимый формат с резервной копией перед изменением. Если файл отсутствует или внешний путь нельзя подтвердить, запись сохраняется и появляется предупреждение. Проверьте восстановление базы вместе с файлами, прежде чем считать резервное копирование рабочим.

## Будущее публичное развёртывание

Публичное развёртывание пока не выполняется. Следующие пункты относятся только к будущему переносу на сервер.

Перед открытием доступа:

- Используйте HTTPS, ограничьте доступ к backend внутренней сетью/loopback и публикуйте только Next.js через reverse proxy. В production cookie имеет `Secure`, `HttpOnly` и `SameSite=Strict`; для разработки по обычному HTTP используйте `npm run dev`. Не отключайте `Secure`, чтобы заставить работать публичный HTTP.
- Reverse proxy должен передавать корректные `Host` и протокол запроса, чтобы проверка полного `Origin` совпадала с адресом браузера. Не принимайте поддельные forwarded-заголовки от произвольных клиентов.
- Создайте администратора через локальную команду, настройте сильный `SECRET_KEY`, проверьте регистрацию и доступность модели ИИ. Не используйте тестовые аккаунты как постоянные.
- Настройте резервное копирование, права доступа к базе/загрузкам, журналирование ошибок без секретов и проверку восстановления.
- Проверьте установленные зависимости; используйте `requirements.lock.txt` вместе с `requirements.txt` для воспроизводимого Python-окружения. Для frontend используйте `npm ci` и существующий lockfile.

Сборка frontend:

```powershell
Set-Location .\frontend
$env:BACKEND_URL = 'http://127.0.0.1:8000'
npm ci
npm run build
npm run start -- --port 3000
```

Текущие эксплуатационные ограничения:

- Ограничения запросов пока хранятся в памяти процесса. Задания ИИ и уведомления сохраняются в SQLite. Для нескольких серверов/реплик необходимы общее ограничение запросов, согласованное хранилище файлов и проверка нагрузки на очередь.
- Лимиты: 300 общих запросов/минуту на IP, 40 операций ИИ/минуту на IP, до 3 одновременных фоновых заданий на пользователя; вход — 40 попыток/15 минут на IP и 12 на аккаунт, регистрация — 8/15 минут на IP. За BFF backend видит IP сервера Next.js, поэтому IP-лимиты могут быть общими для пользователей. Перед масштабированием перенесите ограничения на доверенный входной proxy и в общее хранилище с идентификацией пользователя.
- Проверены существующая SQLite-база и её миграции. Поддержку миграции действующего развёртывания на PostgreSQL, конкурентную нагрузку и распределённое файловое хранилище нужно отдельно подготовить и проверить.
- Предел JSON-запроса backend — 1 МиБ, предел тела Next BFF — 26 МиБ. Изменение `MAX_UPLOAD_BYTES` само по себе не меняет лимит BFF. Архивы Office дополнительно ограничены после распаковки.
- Сетевой вызов ИИ через BFF ограничен 180 секундами. Длительные фоновые задания имеют серверный предел 600 секунд. Для больших аудио/видео нужна отдельная очередь обработки.

Эти ограничения обозначают текущее устройство приложения; прохождение тестов не является независимым аудитом безопасности или проверкой production-нагрузки.
